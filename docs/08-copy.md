# 08. 카피: 사람이 쓴 것처럼

AI로 카피를 쓰면 평균값으로 수렴한다. 어느 제품에나 붙는 형용사, 세워 놓고 넘어뜨리는 대구, 덕담으로 끝나는 마무리가 나온다. 이 문서는 그 평균값에서 벗어나는 규칙이다. 구조와 자리별 길이는 [02-narrative.md](02-narrative.md)를 따르고, 이 문서는 **문장**을 다룬다.

근거:
- [refs/ko-humanizer.md](refs/ko-humanizer.md): 한국어 AI 티 실측. im-not-ai, k-skill, DaleSeo, blader
- [refs/ad-copy.md](refs/ad-copy.md): 사람이 쓴 광고와 랜딩 헤드라인

규칙이 서로 부딪히면 이 순서를 따른다.

1. 사실([templates/content.md](../templates/content.md))
2. 법적 고지
3. 브랜드 보이스
4. 이 문서
5. 린트

## 1. 원칙

1. **사실은 콘텐츠 모델에서만 가져온다.** 수치, 기능, 고객사, 후기는 content.md에 있는 것만 쓴다. 문장을 살리려고 숫자나 사례를 지어내지 않는다. 비어 있으면 묻는다. (네 레포 공통)
2. **모든 문장은 새 정보를 하나 더한다.** 제목을 다시 말하는 문장이나 허전해서 붙인 문장은 지운다. (blader 핵심 규칙, 토스 원칙 3)
3. **형용사 대신 증거를 쓴다.** "빠르다"보다 "3초 만에", "조용하다"보다 "시속 60마일에서 들리는 건 시계 소리"가 낫다. 강한 형용사는 같은 문장에 수치가 있을 때만 쓴다. (Ogilvy Rolls-Royce, DaleSeo 38번 예외)
4. **남이 못 하는 말을 쓴다.** 제품명을 경쟁사 이름으로 바꿔 넣어 보고, 그래도 말이 되면 다시 쓴다. "같지만 다른 은행"은 카카오뱅크에서만 성립하고, "더 스마트한 업무의 시작"은 아무 회사에나 붙는다. (Harry Dry 테스트 3)
5. **흔적 하나보다 무더기를 본다. 그래서 쿼터로 관리한다.** 대구는 페이지에 1개까지 쓴다. 대구 하나는 사람 카피의 힘이고, 섹션마다 같은 틀이 반복되면 AI 티가 된다. (im-not-ai C-8: 사람 필자 532명 중 31명이 대구를 많이 썼다. 판별 기준은 연쇄 반복이다)
6. **소리 내어 읽는다.** 걸리는 곳은 한자어나 번역투이거나, 숨이 차는 쉼표다. (토스 원칙 5, blader "Read it aloud")
7. **구체로 끝낸다.** 섹션과 페이지의 마지막 문장은 덕담이 아니라 사실이나 행동이어야 한다. (blader "End on the last concrete fact")

## 2. 자리별 규칙

| 자리 (content id) | 길이 | 종결 | 쓸 것 | 쓰지 않을 것 |
|---|---|---|---|---|
| `hero.sub` | 한 구절 | 쉼표나 목적절("~할 수 있게,") | 상황이나 감정 하나 | 수치 나열 |
| `hero.h1.short` | 14자 × 2줄 이하(공백 제외) | 동사 또는 카테고리 명사구 하나 | 그림이 그려지는 말, 대표 대구 1개를 여기 쓸 수 있음 | 명사 나열("빠른 · 정확한 · 안전한"), hype 형용사 |
| `hero.body` | 1~2문장 | 페이지 어조 | 기능 2개와 수치 하나 | H1을 풀어서 다시 말하기 |
| 섹션 H2 | 한 문장 | 혜택 문장 | 사용자가 얻는 것, 사용자가 실제로 쓰는 말 | 콜론 부제("자동화: 새로운 차원의…"), 질문형 남발 |
| H3 | 기능 이름 | 명사 | 제품 UI에 있는 이름 그대로 | 매번 바뀌는 동의어 |
| 체크 불릿 | 한 줄 | 항목끼리 종결 통일 | 측정할 수 있는 사실 | "**라벨:** 설명"을 모든 항목에 반복, 항목마다 같은 길이와 틀 |
| 본문 (3문장 이상) | | 페이지 어조 | 단문과 복문 섞기 | 문장마다 연결어미와 쉼표 |
| FAQ 답 | 2~3문장 | 페이지 어조 | **첫 문장에 답**("네.", "아니요."), 그다음에 조건 | "좋은 질문이에요", "도움이 되셨길", 이중 완곡 |
| CTA 버튼 | 2~8자 | "~하기", "~하세요" | 실제 행동("Microsoft 계정으로 시작"), 1인칭 "내 ~" | "지금 바로 경험하세요", "만나보세요" |
| `final` | H1 반복 또는 변주 | | 히어로를 다시 부른다(02 원칙 4) | "지금이야말로", "함께 만들어갈 내일" |

- **히어로와 CTA는 단문이 정상이다.** "단문이 이어지면 AI 티"라는 규칙(im-not-ai E-4)은 3문장 이상인 본문에만 적용한다.
- **불릿과 카드 3장은 허용한다.** 레포들의 "불릿을 산문으로 녹여라"는 칼럼에만 맞는 처방이다. 랜딩에서는 항목마다 길이와 틀이 똑같은 것만 경계한다.
- **H1을 명사구 하나로 끝내는 것은 괜찮다.** 티로("가장 정확한 AI 회의록"), flex, 당근이 이렇게 쓴다. 02의 "동사로 끝낸다"는 명사를 **나열**하는 경우를 막는 규칙이다.

## 3. 사람 카피가 하는 것

모든 예시는 [refs/ad-copy.md](refs/ad-copy.md)에서 가져왔다. 기법은 쓰되, 아래 **조건**을 넘지 못하면 AI 티로 돌아간다.

| 기법 | 예 | 통하는 조건 | 무너지는 경우 |
|---|---|---|---|
| 장면, 구체 명사 | 넥타이와 청바지는 평등하다 / 대출 앞에 작아질 때 | 독자가 머릿속에 그릴 수 있다 | 추상어(경험, 가치, 여정)만 남는다 |
| 부정하며 세우기 | 침대는 가구가 아니라 과학입니다 / 앵무새 답변이 아니라 직접 실행까지 | 지우는 대상이 **구체적이고, 독자가 실제로 그렇게 믿고 있다** | "단순한 툴이 아닙니다"처럼 아무도 하지 않은 주장을 세워 놓고 넘어뜨린다 |
| 대구 | 차이는 인정한다 차별엔 도전한다 / 상담은 채널톡, 업무는 채널웍스 | 두 항이 부딪치고, 소리가 닮고, 둘째 항에서 뒤집힌다 | 섹션마다 같은 틀이 반복된다 |
| 3연 | Wireless. Effortless. Magical. / 1분만에, 은행 방문 없이, 신용점수 영향 없이 | 항목마다 **층위가 다르거나**(스펙 → 경험 → 감정), 사용자가 실제로 하는 걱정을 **하나씩** 지운다 | 같은 층위의 칭찬 셋("빠르고, 안전하며, 편리합니다", "Powerful, durable, and delightful") |
| 숫자 | 3분이면, AI 상담원이 첫 인사를 합니다 / 1,000 songs in your pocket | 단위가 생활 단위다(분, 곡, 건, 원) | 출처 없는 "수많은", "다양한" |
| 의외의 동사 | 진심이 짓는다 / 콘덴싱이 옳았다 | 업종의 동사이거나 사람의 동사다 | 제공합니다, 지원합니다, 경험하세요 |
| 생략 | 간 때문이야 / 금융을 내 편으로 | 독자가 빈칸을 바로 채운다 | 생략이 너무 많아 설명이 필요해진다 |
| 대사, 호명 | 여보! 아버님 댁에… / 경희야, 넌 먹을 때가 제일 이뻐 | 특정한 사람이 특정한 상대에게 하는 말이다 | 불특정 "여러분", "당신" |
| 약점 인정, 상식 뒤집기 | Think small. / 잠시 꺼두셔도 좋습니다 | 업계가 모두 반대로 말하고 있다 | 뒤집을 상식이 없는데 반전만 흉내 낸다 |
| 1인칭 "내" | 내 숨은 환급액을 찾아보세요 / 내 환급액 조회하기 | 결과가 사용자 개인의 것이다 | 번역투 "당신의", "여러분의" |

**말을 캐는 곳**: 좋은 문장은 지어내기보다 찾아낸다. Ogilvy는 Rolls-Royce 문장을 3주 동안 조사해서 찾았다. 리뷰, 사내 슬랙, 인터뷰에서 사용자가 쓴 말을 그대로 content.md에 옮겨 두고 카피의 재료로 쓴다(Copyhackers VoC). 영어 리뷰를 번역해서 쓰지 않는다.

## 5. 주의 (S2: 페이지 쿼터를 넘으면 고친다)

| 패턴 | 쿼터 (페이지 전체) | 처방 |
|---|---|---|
| 대구 "A가 아니라 B", "X를 넘어 Y" | 1 | 대표 대구 하나만 남기고 나머지는 긍정문으로 바꾼다 |
| hype 형용사(혁신적, 획기적, 압도적, 새로운 차원, 한 단계 더, 완벽한) | 0. 단, 같은 문장에 수치가 있으면 허용 | 수치, 화면, 고유명사로 바꾼다 |
| 매끈한 부사(손쉽게, 간편하게, 원활하게, 스마트한, 다양한, 효율적인) | 1 | 무엇이 얼마나 쉬운지 쓴다: "버튼 하나", "로그인 없이" |
| "~를 통해", "~에 대해", "~와 관련된", "~에 기반한" | 2 | "~로", "~를"로 바로 잇는다. 사람도 자주 쓰는 표현이라 한두 번은 둔다 |
| "~할 수 있습니다" | 2 | 증거가 있는 혜택은 단정한다. 진짜 가능성이나 허가("되살릴 수 있어요")는 둔다 |
| 연결어미 뒤 쉼표("녹음되고, 회의록은") | 3 | 빼고 읽어서 숨이 차지 않으면 뺀다. 한국어 AI 판별에서 가장 강한 지표다(KatFishNet AUC 94.88%) |
| 은유 | 1 | 브랜드 은유 하나만 쓴다. "묵직한 성능" 같은 감각 술어는 한 번만 나와도 고친다 |
| 질문형 훅 | 2 | Hook과 Turn에만 쓴다(02 카피 규칙) |
| 같은 대상의 동의어 돌려쓰기 | 0 | 기능명은 content.md의 H3 이름 하나로 통일한다 |

## 6. 표기

- **어조는 페이지 전체에서 하나로 쓴다.** 해요체로 갈지 합니다체로 갈지는 브리프에서 정한다. H1의 명사형이나 한다체 종결은 어조와 별개로 허용한다. 한 단락 안에서 섞지 않는다(DaleSeo style-guide). 변주는 어미를 바꾸지 말고 문장 길이로 준다.
- **숫자**: 통계, 금액, 시간은 아라비아 숫자로 쓰고 단위와 붙인다(3초, 30일, 4,300만). 관용 표현은 한글로 쓴다(한두 번). 같은 종류의 수치는 한 표기로 통일한다.
- **범위**: 숫자 사이에만 –를 쓴다(14:00–14:30). 문장 안에서 줄표는 쓰지 않는다.
- **가운뎃점**: 짝을 이루는 짧은 묶음에만 쓴다(PC · 모바일). 세 개 이상을 나열할 때는 쉼표를 쓴다.
- **강조**: 수단을 하나로 정한다. Clear에서는 숫자만 브랜드 색으로 칠한다(02). 굵게, 따옴표, 색을 같은 용도로 섞지 않는다.
- **화살표**: →만 쓴다.
- **영어 병기**: 첫 등장에만 괄호로 병기한다. 제품명과 표준 약어(AI, MCP, API)는 그대로 둔다.
- **링크 문구**: "여기", "클릭" 대신 무엇으로 가는지 쓴다.

## 7. 고치지 않는 것 (오탐)

- 사실, 수치, 고유명사, 인용, 법적 고지, 녹음 고지 같은 안전 문구
- 진짜 가능성이나 허가를 말하는 "~할 수 있다". 이걸 단정형으로 바꾸면 과장 광고가 된다.
- 구체적인 행동 순서를 나열한 3연. 예: "보고하고, 권한을 주고, 고치고, 다시 AI에게 물어요"
- 사람이 원래 더 많이 쓰는 표현의 한두 번 사용: "~에 대해", "~를 통해", "~을 위해", "것이다"(im-not-ai 실측)
- 화자 개입("솔직히", "직접 써 보면"). 한국어에서는 사람 쪽 신호다(im-not-ai DS-4).
- 반듯한 맞춤법, 짧고 단호한 문장 하나, 개조식 목록 자체(k-skill 오탐 목록)

## 8. 작업 절차

**새로 쓸 때**
1. content.md에 주장과 증거, 사용자가 실제로 쓴 말부터 채운다.
2. 자리별 길이에 맞춰 초안을 쓴다. 대표 대구와 브랜드 은유를 쓸 자리를 미리 정한다.
3. `python3 tools/copy_lint.py sites/<제품>/content.md`
4. 감사 질문 다섯 개를 묻는다.
   - 이 페이지에서 아직 AI 같은 문장은 어디인가?
   - 제품명을 경쟁사로 바꿔도 성립하는 문장은?
   - 그림이 그려지지 않는 문장은?
   - 지워도 뜻이 같은 문장은?
   - 마지막 문장이 덕담인가?
5. 소리 내어 읽는다.

**기존 카피를 고칠 때**
1. 문장마다 뜯어고치지 않는다. 페이지를 지배하는 패턴 3~6개를 먼저 고른다(im-not-ai 진단 단계).
2. 걸린 구간만 고친다. 고친 뒤 원문과 비교해 사실과 수치가 그대로인지 확인한다.
3. 문자 변경률이 30%를 넘으면 멈추고 사용자에게 확인한다. 고치다가 새 흔적을 만들지 않는다. 특히 대구, "결국", 쉼표를 새로 넣지 않는다.

## 9. 린트

`tools/copy_lint.py`는 §4와 §5의 패턴을 정규식으로 찾는다. content.md의 표 행이나 index.html의 텍스트를 읽는다. 함께 검사하는 것은 이렇다.
- `hero.h1.short`의 14자 제한
- 한 단락 안에서 합니다체와 해요체가 섞였는지

S1이 남으면 exit 1로 끝난다. 린트는 1차 거름망이다. 걸린 줄은 §7을 보고 사람이 판단하고, 안 걸렸다고 통과로 보지 않는다. 쿼터나 패턴을 바꾸면 이 문서와 `RULES` 표를 같은 커밋에서 고친다.
