# 07. 여러 버전 제시하기

제품 하나에 랜딩 하나를 만들지 않는다. **같은 콘텐츠로 성격이 다른 2~3개 버전**을 만들어 보여주고 고르게 한다. 버전끼리 다른 것은 표현이고, 사실은 다르지 않다.

## 두 극과 그 사이

| | **Film** (화려) | **Hybrid** | **Clear** (깔끔한 정보전달) |
|---|---|---|---|
| 레퍼런스 | — | 두 레퍼런스의 조합 | [Tiro](refs/tiro-teardown.md) |
| 골격 | 고정된 스크롤 필름 1편과 챕터 → 제품 투어 → 포스터 CTA | Clear의 골격 위에 **히어로만** 짧은 필름(3~4비트), 또는 sticky 제품 투어 | 섹션을 위에서 아래로 쌓은 구조: 히어로 → 데모 → 신뢰 → 기능 → 보안 → 가격 → FAQ → CTA |
| 주인공 | 그림으로 만든 세계와 카메라 | 첫 화면의 몰입, 그다음은 스캔하기 쉬운 정보 | **스크립트로 움직이는 HTML 제품 데모** |
| 모션을 움직이는 것 | 스크롤 진행값(rAF, 셰이더) | 히어로는 스크롤, 나머지는 시간·뷰포트 진입 | 시간 기반 상태머신과 CSS 키프레임 |
| 비주얼 | 에디토리얼 세리프, 어두운 필름, 질감 | 혼합. 토큰은 하나로 통일한다 | 따뜻한 무채색, 브랜드 1색, 평면, 헤어라인 |
| 티어 | T1~T3 | 히어로 T1, 나머지 T0 | T0 |
| 필요 에셋 | 장면 플레이트, 영상 체인, 투어 | 장면 3~4개와 데모 또는 스크린샷 | 데모 스크립트와 스크린샷 카드 |
| 제작 난이도 | 높음 | 중간 | 낮음~중간 |
| 잘 맞는 곳 | 브랜드 런칭, 플래그십, 이야기가 핵심인 제품 | 브랜드 인상과 전환을 둘 다 잡아야 할 때 | B2B 구매자, 비교·검토하는 방문자, 다국어, 빠른 출시 |
| 약한 곳 | 정보를 빨리 찾기 어렵다. 무겁다. 모바일 비용이 크다 | 두 문법이 어긋나 보일 위험이 있다 | 기억에 남는 순간이 약하다 |

## 버전 = 골격 × 룩

위 표의 Film, Hybrid, Clear는 **골격**이다. 골격 위에 **룩**을 하나 입히면 버전 하나가 된다. 같은 골격에 룩만 바꿔도 전혀 다른 페이지가 나온다.

| 룩 | 레퍼런스 | 만드는 방식 | 비용 | 어울리는 골격 |
|---|---|---|---|---|
| **페인터리 필름** | — | 손그림이나 AI 4K 플레이트, 카메라, 셰이더 전환 | 높음(그림 퀄리티가 관건) | Film, Hybrid 히어로 |
| **AI 디오라마 플라이스루** | [scroll-world](refs/scroll-world.md) | Seedance 영상 체인 스크럽(T2) | 클립당 약 23크레딧 | Film, Hybrid 히어로 |
| **페이퍼 콜라주 스톱모션** | [pasteup](refs/pasteup.md) | AI로 컷아웃 요소를 만들고 배경을 지운 뒤 DOM에서 조립. 2프레임마다 포즈, 시드 지터 | 낮음(요소당 약 3크레딧, 영상 0) | **모든 골격.** Clear의 섹션 조립에도 쓸 수 있다 |
| **코드 드로잉 스타일** | [lemo-opuscar](refs/lemo-opuscar.md) | `render(progress)` 결정적 캔버스/WebGL(코드 필름 티어). **룩 하나가 아니라 51종 묶음**이라 스타일마다 별도 룩으로 세운다(적합도 표는 refs) | 에셋은 거의 0, 개발 시간이 든다 | Film, Hybrid. living-screencast는 Clear 데모 |
| **웜 미니멀** | [Tiro](refs/tiro-teardown.md) | 스크린샷 카드, HTML 데모, 표면 리듬 | 낮음 | Clear |
| **메타포 다이어그램 · 키네틱 디스플레이** | [Studios 따따디](refs/sddaddad-teardown.md) | 검정 바탕, 초대형 컨덴스드 이탤릭, 핫 액센트 1색(+보조 1색). 브랜드 은유를 SVG로 그리면 선이 저절로 그려지고, `offset-path` 위로 작은 오브젝트가 돈다. 커튼 리빌과 마스크 라인 상승이 이어지고, 이징 곡선은 하나로 통일한다. 스텝은 접근 가능한 NEXT/BACK 버튼이나 스크롤로 넘긴다 | 0크레딧 | Hybrid, Film(짧게) |
| **클리어 + 시네마틱 메커니즘 1장** | [Homeflix](refs/homeflix-teardown.md) | 흰 바탕과 잉크에 일렉트릭 액센트 1색을 "빛"처럼 쓴다. 섹션 오프너(56px 잉크 틱 룰), 실크 이징 `cubic-bezier(.34,.02,.16,1)`, 정직한 인트로 로더, 마스크 라인 리빌, 계단식 카드 + 호버 언폴드. 화려함은 **sticky 스크롤 three.js 파티클 장면 하나**에만 몰아준다 | 0크레딧(three.js) | Clear + 장면 1개 |

예를 들어 같은 제품으로 이렇게 세 개를 낼 수 있다:
- A. Clear × 웜 미니멀(기본, 가장 빠름)
- B. Hybrid × 페이퍼 콜라주(히어로가 조립되고, 아래는 Clear)
- C. Film × 코드 드로잉 또는 AI 디오라마(브랜드 순간)

룩은 [templates/look.md](../templates/look.md) 양식으로 스펙을 고정한다.

## 그 밖의 변주 축

한 번에 축 하나만 바꿔야 비교가 된다.

| 축 | 선택지 |
|---|---|
| 히어로 장치 | 스크롤 필름 / 라이브 데모 / 키네틱 타이포 / 콜라주 조립 / 정지 키 비주얼 |
| 증거 방식 | 실제 앱 iframe 투어 / 스크립트 HTML 데모 / living-screencast(마스코트가 UI 안에서 연기) / 스크린샷 카드 |
| 톤 | 웜 라이트(Tiro) / 다크 필름 / 에디토리얼 페이퍼 / 단색 필드(콜라주) |
| 밀도 | 챕터 몇 개 / 섹션 10개 이상 |

## 공통 콘텐츠 모델: 버전을 싸게 만드는 핵심

모든 버전은 **같은 콘텐츠 파일 하나**를 읽는다. 양식은 [templates/content.md](../templates/content.md)에 있다. 제품을 받으면 이 파일부터 채우고, 레이아웃은 그 뒤에 만든다.

```
content (사실·주장·증거·카피 블록)
   ├── Film 레이아웃   → scenes[]  (비트마다 콘텐츠 블록 id를 참조)
   ├── Hybrid 레이아웃 → hero scenes[] + sections[]
   └── Clear 레이아웃  → sections[]
```

- **주장마다 증거를 붙인다.** 증거가 없는 주장은 어느 버전에도 넣지 않는다.
- **카피는 길이별로 미리 써 둔다.** Film은 헤드라인 14자 2줄, Clear는 H2·H3·체크 불릿 3~5개처럼 필요한 길이가 다르다.
- **데모 스크립트도 하나다.** Film의 투어 스텝, Hybrid의 투어, Clear의 히어로 데모가 같은 시나리오를 다른 길이로 재생한다.
- CTA, FAQ, 신뢰 요소(인증, 고객사, 후기)는 버전과 상관없이 같다.

## 제시 순서 (충실도를 단계별로 올린다)

1. **컨셉 카드**(버전마다 1장): 한 줄 콘셉트, 히어로 목업 1장, 섹션 흐름, 필요 에셋, 기간, 비용(AI 크레딧 포함), 리스크. 여기서 1~2개로 좁힌다.
2. **히어로와 섹션 1개 시안**: 실제 콘텐츠로 첫 화면과 대표 섹션 하나만 동작하게 만든다. 브라우저 URL로 비교한다.
3. **풀 빌드**: 고른 버전만 [01-process.md](01-process.md)의 4~8단계를 끝까지 진행한다.

- **Clear를 먼저 만든다.** 가장 싸고, 콘텐츠 모델에 빈 곳이 있는지 가장 빨리 드러난다. Film과 Hybrid는 검증된 콘텐츠 위에 얹는다.
- 비교 페이지 하나에 버전별 미리보기 링크와 컨셉 카드를 나란히 둔다. 결정 기준은 아래 표를 쓴다.

## 고르는 기준

| 질문 | Film 쪽 | Clear 쪽 |
|---|---|---|
| 주 방문자가 이미 제품을 알고 비교 중인가? | 아니다(처음 본다) | 그렇다 |
| 이 페이지의 성공 지표는? | 브랜드 인상, 공유, 체류 | 가입, 문의, 다운로드 전환 |
| 데모 빌드나 실제 UI가 있는가? | 있으면 투어로 넣는다 | 없으면 스크립트 HTML 데모를 만든다 |
| 에셋 예산과 기간 | 그림·영상 제작 여력이 있다 | 2주 안에 출시해야 한다 |
| 모바일 비중 | 낮다 | 높다(무게가 적고 스캔이 쉽다) |
| 다국어 | 비용이 언어 수만큼 늘어난다 | 쉽다 |

## 버전 간 공통 규칙

- 디자인 토큰 세트는 하나로 쓰고, 버전은 그 안에서 표면과 밀도만 바꾼다. Hybrid가 어긋나 보이는 원인은 대부분 토큰이 둘로 갈라진 데 있다.
- 섹션 id와 분석 이벤트는 버전과 상관없이 같은 이름을 쓴다(`hero`, `demo`, `proof`, `features`, `security`, `pricing`, `faq`, `final`). 그래야 버전끼리 전환율을 비교할 수 있다.
- [06-quality-gate.md](06-quality-gate.md)는 모든 버전에 똑같이 적용한다.
