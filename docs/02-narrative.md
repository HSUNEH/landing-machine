# 02. 내러티브 · 정보 구조 · 카피

## 원칙

1. **이야기 먼저, 기능 나중.** 기능 목록으로 시작하면 아무리 화려하게 만들어도 기능 목록 페이지가 된다.
2. **비트 하나에는 역할 하나.** 한 장면에서 분위기를 잡으면서 기능까지 설명하려 하지 않는다.
3. **증거는 이야기 세계 안에서 등장시킨다.** 제품 화면을 별도 섹션에 붙이지 않고, 장면 속 폰이나 모니터에 띄운다.
4. **시작과 끝이 서로를 받는다.** 마지막 문장이 앞 장면의 문장을 다시 부른다.

## 기본 구조: "하루의 삶"

| # | 역할 | 쓸 수 있는 곳 |
|---|---|---|
| 1 | **Hook**: 분위기와 질문 | 모든 제품 |
| 2 | **Proof**: 결과물이 세계 안에 등장 | 결과물이 화면으로 보이는 제품 |
| 3 | **Turn**: "어떻게?" | 작동 원리가 보이지 않는 제품 |
| 4 | **How**: 번호 붙은 3~6단계 메커니즘을 은유로 | 자동화, AI, 워크플로 |
| 5 | **Return**: 사람에게로 돌아오기 | 협업, B2B |
| 6 | **Tour**: 실제 UI 직접 보기 | 데모 빌드가 있는 경우 |
| 7 | **FAQ** | 공통 |
| 8 | **Poster CTA** | 공통 |

챕터는 3개 정도로 묶는다. 챕터 메뉴("장면 바로가기")와 세로 챕터 태그는 이 묶음을 기준으로 만든다.

## 다른 구조 후보

제품 성격에 맞춰 고른다. 처음부터 섞지 않는다.

- **여정 / 가치사슬**(scroll-world): 원료에서 제조, 매장, 배송, 커뮤니티, 히어로 제품 순으로 간다. 물리적인 공정이 있는 제품에 맞는다. 장면은 5~7개가 적당하다.
- **비포 / 애프터**: 문제 상황에서 전환을 거쳐 해결된 상황으로 간다. 장면 수가 적어 싸게 만들 수 있다.
- **제품 하나 해부**(스크롤 3D): 히어로 오브젝트 하나를 회전시키며 부위별 문구를 3개 띄운다. 하드웨어와 신제품 런칭에 맞는다.

## 정보전달형 구조: 섹션 스택과 신뢰 스택

필름 없이 섹션을 위에서 아래로 쌓는 구조다. 방문자가 **훑어보며 판단**할 수 있게 만든다. [07-versions.md](07-versions.md)의 Clear 버전이 이 구조를 쓴다.

| # | 섹션 (id) | 역할 | 실측 예 |
|---|---|---|---|
| 0 | 헤더 | 내비게이션, 문의 | 고정, 크림 배경에 blur, 헤어라인. 오른쪽에 "도입 문의" 필 |
| 1 | `hero` | 가치 제안 | 신뢰 칩(ISO·SOC2) → 서브라인 "대화에만 집중할 수 있게," → H1 "가장 정확한 AI 회의록" → 본문(강조 구절 굵게) → CTA 2개 |
| 2 | `demo` | **제품이 동작하는 모습** | 히어로 바로 아래에 HTML로 재현한 제품. 스크립트로 재생되고, 마지막에 "기록 종료"를 누르게 한다 |
| 3 | `proof` | 사회적 증거 | "이미 **300+개 기업**이…"(숫자만 브랜드 색), 로고가 양방향으로 흐르는 마키 |
| 4 | `testimonials` | 사회적 증거 | 이름, 직함, 회사가 붙은 후기 6개(캐러셀) |
| 5–8 | `features-n` | 기능 4묶음 | 섹션마다 H2(혜택) → H3(기능)과 체크 불릿, 같은 틀의 이미지 카드 |
| 9 | 밴드 | 분위기 전환 | 처음 나오는 어두운 섹션. 대표 AI 기능 하나만 보여준다 |
| 10 | `security` | 엔터프라이즈 신뢰 | 통제 항목 6개 카드, 인증 배지, "엔터프라이즈 문의" |
| 11 | `pricing` | 플랜 | 월/연 토글, 무료 체험 카드 |
| 12 | `faq` | 반론 처리 | 아코디언 8개(첫 항목은 펼쳐 둔다). JSON-LD `FAQPage`로도 내보낸다 |
| 13 | `final` | 히어로 반복 | 히어로의 서브라인과 H1을 다시 쓰고 같은 CTA를 둔다 |
| 14 | 푸터 | 링크 | API·MCP 같은 개발자 도구, **경쟁사 비교 페이지 링크** |

**신뢰 스택**은 위에서부터 이렇게 쌓인다: 인증 칩(H1 위) → 로고 → 실명 후기 → 보안 섹션 → 팀/엔터프라이즈 플랜 → FAQ → 경쟁사 비교. B2B 구매자가 내부 보고에 쓸 근거를 모두 페이지 안에서 찾을 수 있게 하는 순서다.

정보전달형 카피 패턴:
- **서브라인 → H1 → 본문**의 3단. 서브라인은 상황이나 감정("대화에만 집중할 수 있게,"), H1은 카테고리 + 최상급("가장 정확한 AI 회의록"), 본문은 기능 2개와 강조 수치("**3초 만에 완성**")를 담는다.
- 섹션 H2는 **혜택 문장**("언제 어디서나, 어떤 언어든 걱정 없어요"), H3는 **기능 이름**, 불릿은 **측정 가능한 사실**("발화 0.5초 이내 텍스트 변환")로 쓴다.
- 수치 문장에서는 숫자 부분만 브랜드 색으로 칠한다.
- 마지막 CTA 섹션은 히어로를 그대로 다시 부른다. 위에서 말한 "시작과 끝이 서로를 받는다" 원칙과 같다.

## 비트 표 템플릿

```
| id | 챕터 | 역할 | vh | eyebrow | 헤드라인(줄바꿈 /) | sub | 화면 | 전환(in) |
|----|------|------|----|---------|-------------------|-----|------|----------|
| s0 | I    | hook | 145| 00·<단어> | <헤드라인 1줄> / <2줄> | — | <장면> | — |
```

- `vh`: 그 비트의 스크롤 길이. 히어로와 증거 비트는 길게(200~280vh), 이동 비트는 짧게(115~170vh) 잡는다. 모바일에서는 0.65배 정도로 줄인다.
- **필름 안 카피는 짧게 쓴다.** 필름 자막은 콘텐츠의 제목과 첫 구절까지만 넣고, 나머지는 그림·UI 동작·라벨이 맡게 한다. 문장 전체는 필름 바로 뒤 스캔 섹션("쓰는 법" 등)으로 옮긴다. 읽기 시간 규칙(refs/lemo-opuscar.md)은 글자 수에 비례해서, 문장을 통째로 넣으면 필름이 길어진다. 2026-10-19 시안 두 개는 처음에 1875vh, 2127vh였고, 이 규칙을 적용해 각각 895vh, 897vh로 줄였다. 같은 규칙을 처음부터 적용한 시안은 800~900vh였다. **기본 예산은 필름 데스크톱 900vh 이하, 모바일 700svh 이하**로 잡고, 넘으면 이유를 look.md에 적는다.
- `eyebrow`: `번호·단어` 형태로 짧게 쓴다. 모노 서체, 대문자 감각으로 처리한다.

## 카피 규칙

문장 단위 규칙(AI 티 금지 목록, 쿼터, 표기)은 [08-copy.md](08-copy.md)에 있다. 여기는 길이와 형식만 다룬다.

- **헤드라인**: 1~2줄이고, 히어로 크기에서 한 줄 **14자 이하**(한글 기준)다. 줄바꿈 위치를 직접 지정한다(`/`).
- **단계 캡션**: `01 · 업무 접수`처럼 번호, 빨간 점, 단어 순으로 쓴다. 본문은 한 문장이다.
- **서브 / 본문**: 방문자 입장에서 평이하게 한 문장으로 쓴다. scroll-world 규칙은 eyebrow 2~4단어, title 3~6단어, body 1문장, tag 0~3개다.
- **질문형 훅**은 이야기 전체에서 두 번 이하로 쓴다. Hook과 Turn에만 쓴다.
- **동사로 끝낸다.** "~합니다", "~찾습니다"처럼 쓰고, 명사로 끝나는 나열은 피한다. 단, H1 하나를 카테고리 명사구로 끝내는 건 괜찮다("가장 정확한 AI 회의록").
- 한국어와 영어를 같은 DOM id로 관리한다. 영어는 같은 자리에 같은 길이 감각으로 들어가야 하며, EN 헤드라인은 자간을 더 좁힌다(-0.045em).

## 접근성 관점의 정보 구조

- 필름이 보이지 않아도(WebGL 없음, reduced-motion) **카피만으로 이야기가 성립**해야 한다. 헤드라인은 실제 DOM 텍스트(`h1`, `h2`)로 두고, 그림 속 글자로 넣지 않는다.
- 장면을 건너뛰면 라이브 리전으로 알린다("… 장면으로 이동했습니다").
- 딥링크를 지원한다(`#s5`, `?p=0.42`, `#productTour`).
