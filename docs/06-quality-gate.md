# 06. 품질 게이트

출시 전에 전부 체크한다. "브라우저로 직접 확인함"이 아니면 체크하지 않는다.

## 내러티브와 비주얼

- [ ] 필름을 끄고 카피만 읽어도 이야기가 이어진다.
- [ ] 히어로 헤드라인은 한 줄 14자 이하, 2줄 이하이며, 줄바꿈을 직접 지정했다.
- [ ] 한국어 본문은 17px 이상이고 `keep-all`이 걸려 있다.
- [ ] 모든 장면 스틸을 한 화면에 늘어놓았을 때 각도, 팔레트, 빛이 일치한다.
- [ ] 브랜드 포인트 색은 1색이며, 정해 둔 자리에만 쓰였다.
- [ ] 마지막 CTA는 하나이고, 헤더 CTA와 같은 행동을 가리킨다.

## 카피 ([08-copy.md](08-copy.md))

- [ ] `python3 tools/copy_lint.py`를 content.md와 index.html에 돌려 S1이 0이다. 남은 S2는 한 줄씩 읽고 08 §7(오탐)에 해당하는지 판단했다.
- [ ] 제품명을 경쟁사 이름으로 바꿔 넣어도 성립하는 헤드라인이 없다.
- [ ] 대구("A가 아니라 B")는 페이지에 1개 이하이고, 지우는 대상이 구체적이다.
- [ ] 강한 형용사는 같은 문장에 수치가 있을 때만 쓰였다. 모든 수치는 content.md의 증거와 일치한다.
- [ ] 페이지 어조가 하나다. 한 단락 안에서 합니다체와 해요체가 섞이지 않는다.
- [ ] FAQ 답은 첫 문장에 답이 있다.
- [ ] 소리 내어 끝까지 읽었다.

## 모션

- [ ] 스크롤 하이재킹이 없다. 휠, 키보드, 스크롤바, 터치가 모두 네이티브로 동작한다.
- [ ] 정지 상태에서 rAF가 멈춘다. 퍼포먼스 패널에서 유휴 상태일 때 프레임이 없는지 확인한다.
- [ ] 스크럽 연출이 결정적이다. 같은 진행값으로 앞으로 오든 뒤로 오든 같은 그림이 나온다(스크린샷을 비교한다).
- [ ] 읽기 시간: 카피가 온전히 보이는 구간이 (한국어 글자 수 ÷ 4.5 + 1.5)초 이상이다. 영어는 ÷ 15. 프로젝트에서 정한 기준 속도로 자동 스크롤해 측정한다.
- [ ] 이음새 직전과 직후를 스크린샷으로 비교해, 장면 구성이 툭 튀지 않는다(T2).
- [ ] 거꾸로 스크롤해도 되감기처럼 덜컹거리지 않는다.
- [ ] 장면 바로가기와 딥링크(`#id`, `?p=`)로 이동하면 해당 장면이 바로 그려진다.

## 성능

- [ ] JS 없이도 첫 페인트가 나온다(sticky stage의 CSS 배경).
- [ ] 스플래시는 첫 장면이 실제로 그려진 뒤에 사라지고, 사용자가 스크롤하면 바로 걷힌다.
- [ ] 현재, 이전, 다음 장면의 리소스만 메모리에 올라와 있다.
- [ ] 제품 투어로 들어가면 필름 렌더러가 파킹된다. 무거운 렌더러는 하나만 살아 있다.
- [ ] DPR은 2 이하로 제한한다. 프레임이 26ms를 넘는 일이 이어지면 효과 품질을 낮추고 DPR을 내리는 적응형 장치가 있다(T3).
- [ ] 데스크톱에서 LCP, CLS, INP를 측정했고, 모바일은 CPU를 4–6배 스로틀한 상태에서 측정했다.
- [ ] 해시가 붙은 에셋은 immutable 캐시로 내보낸다.

## 접근성과 폴백

- [ ] `prefers-reduced-motion`일 때 스무딩, 자동 스크롤, 드래그, 키프레임 애니메이션, 스냅이 꺼지고, 스크립트 이동은 즉시 이뤄진다.
- [ ] WebGL2가 없거나 영상 재생에 실패하면 **스틸 크로스페이드(T1)로 대체**된다. 안내문만 띄우고 끝내지 않는다.
- [ ] 챕터 메뉴는 `<dialog>`와 `showModal()`로 만들었고, 포커스 트랩, ESC 닫기, 열었던 자리로 포커스 복귀, `aria-current`가 동작한다.
- [ ] 장면 이동은 라이브 리전으로 알린다.
- [ ] 제품 데모 iframe에는 `inert`를 주고, 같은 정보를 부모 DOM 텍스트로도 제공한다.
- [ ] 키보드만으로 처음부터 CTA까지 갈 수 있다.

## 모바일

- [ ] 필름 길이를 줄였다(≈0.65배).
- [ ] 세로 화면용 카메라와 크롭에서 주인공이 화면 안에 있다.
- [ ] 높이에는 `svh`/`dvh`를 쓴다. URL 바가 접힐 때 페이지가 튀지 않는다(높이만 바뀌는 resize는 무시한다).
- [ ] `viewport-fit=cover`와 safe-area inset을 적용했다.
- [ ] iOS Safari에서 첫 장면이 빈 화면으로 나오지 않는다(포스터를 유지하고, 첫 터치에 영상을 prime한다).
- [ ] 빠르게 플릭해도 영상이 멈추지 않는다(seek를 합치고, `-g 4` 인코딩을 쓴다).
- [ ] `overscroll-behavior-y: none`

## 로딩 함정 (실측에서 확인한 것)

- [ ] CTA는 **서버에서 기본값을 렌더**하고, OS 판별은 하이드레이션 뒤에 다듬는다. 클라이언트에서만 그리면 CTA가 늦게 튀어나오고 레이아웃이 밀린다.
- [ ] 첫 화면 아래에 있는 이미지에 `priority`나 preload를 걸지 않는다.
- [ ] 이미지 품질을 100으로 두지 않는다. CSS 배경 사진도 최적화 파이프라인을 거친다(레퍼런스의 보안 배너는 PNG 2.44MB였다).
- [ ] 랜딩 번들에 앱 셸, 전체 i18n, 분석 SDK 묶음이 섞이지 않는다.
- [ ] 스크립트 데모는 화면에 보일 때만 재생되고, 별도 청크로 분리되어 있다.

## 계측

- [ ] 섹션 id(`hero`, `demo`, `proof`, `features`, `security`, `pricing`, `faq`, `final`)마다 노출 이벤트를 보낸다(IntersectionObserver, threshold 0.15).
- [ ] 스크롤 깊이 25/50/75/100% 이벤트를 보낸다.
- [ ] 버전끼리 이벤트 이름이 같다(버전 비교용).

## 다국어와 메타

- [ ] KO/EN이 같은 DOM id를 쓰고, 스크린샷도 언어별로 따로 있다.
- [ ] OG 이미지, theme-color, hreflang, title, description을 넣었다.
- [ ] JSON-LD를 넣었다: Organization, SoftwareApplication, FAQPage(FAQ 섹션과 같은 데이터에서 만든다).
