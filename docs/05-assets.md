# 05. 에셋

## 가장 중요한 원칙: 한 세계로 보여야 한다

필름 효과의 설득력은 엔진이 아니라 **아트 디렉션의 일관성**에서 나온다. 각도, 팔레트, 빛, 질감이 한 장이라도 어긋나면 그 장면에서 바로 몰입이 깨진다.

- AI로 생성할 때는 **스타일 프리앰블을 모든 프롬프트에 글자 하나 다르지 않게** 붙인다.
- 장면 스틸은 **한 가지 소스, 한 가지 모델**로만 만든다. 소스를 섞으면 스타일이 미묘하게 흔들린다.
- 어긋난 한 장은 이미 승인된 장면을 참조 이미지로 넣어 다시 생성한다. 단, 포토리얼 실내는 참조 이미지를 넣으면 같은 방이 복제되므로 넣지 않는다.

## AI 생성 파이프라인 (scroll-world 방식)

자세한 내용은 [refs/scroll-world.md](refs/scroll-world.md)에 있다. 요약:

1. **스틸**: 장면 N개를 동일한 프리앰블로 생성한다. 3:2, 2k. 모두 늘어놓고 한 세계로 보이는지 검토한다.
2. **장면 클립**: 스틸을 start-image로 넣어 카메라가 장면으로 다이브하는 클립을 만든다(8~10초).
3. **커넥터**: start = 앞 클립의 **실제 마지막 프레임**, end = 다음 클립의 **실제 첫 프레임**. 원본 스틸을 넣으면 이음새에서 장면이 툭 튄다.
4. **카메라 구조**는 미리 정한다.
   - A. 연속 전진: 이전 클립의 마지막 프레임에서 다음 클립을 이어 만든다. end-image는 넣지 않는다. 사실적인 공간에 맞는다.
   - B. 다이브와 공중 이동: 미니어처·디오라마 세계에 맞는다.
5. **프리비즈**를 먼저 한다. 480p·720p로 체인 전체를 돌려 본 뒤 최종 해상도로 다시 렌더한다. 비용은 생성 전에 사용자에게 알리고 승인을 받는다. 참고로 6장면 1080p 체인이 약 27달러였다(2026-07 측정).
6. **모바일**: 9:16 체인을 따로 렌더한다. 16:9 클립을 가운데만 잘라 쓰는 건 임시방편이고, 그렇게 내보낼 때는 반드시 명시한다.

### 생성 모델 구성

이미지·영상 생성 도구 하나로 scroll-world의 Higgsfield·Monid 역할을 모두 대신할 수 있다. 아래는 단계별 모델 구성이다.

| 파이프라인 단계 | 작업 / 모델 | 비고 |
|---|---|---|
| 장면 스틸 | `text-to-image` · **GPT-Image-2** (scroll-world 기본값과 같다). 대안: Nano Banana Pro, Seedream 5.0 Pro | 견적 3크레딧/장 |
| 스타일 고정 재생성 | `image-edit` (승인된 장면을 참조로) | |
| 플로팅 장면 배경 제거 | `bg-removal` · Bria | `knockout.py` 대체 |
| 4K 플레이트 (T1) | `image-upscale` · SeedVR / Topaz | 스틸 필름에 필요한 4K 소스 |
| 다이브 / 레그 | `image-to-video` · **Seedance 2.0** (`first_frame`, 480p–4K, 4–15초) | 체인 모델 |
| 커넥터 | 같은 모델에 `first_frame`과 `last_frame`을 함께 넣는다 | **체인 전체를 한 모델로** 간다 |
| 프리비즈 | `image-to-video` · Seedance 2.0 Fast (480/720p, last_frame 지원) | scroll-world의 `seedance_2_0_mini`에 해당 |
| 필터 우회용 대체 | Kling Video 3.0 Pro/Standard (last_frame 지원, 3–15초) | 클립 한두 개에만 쓴다 |

필수 파라미터:
- `generate_audio: false`로 준다. 기본값은 true다.
- `aspect_ratio: "16:9"`(모바일은 `"9:16"`)를 **명시**한다. 기본값 `auto`는 입력 이미지의 비율을 따라가기 때문이다.
- 생성 전에 견적을 내고 사용자에게 승인을 받는다.

#### 검증 결과 (2026-10-16)

스틸 2장을 만들고, 그 둘을 잇는 커넥터 클립(A→B, 480p, 5초)을 2개 만들어 확인했다. 총 47크레딧이 들었다.

| 항목 | 결과 |
|---|---|
| Seedance 2.0: 첫 프레임과 입력 A | **31.0dB**. 첫 프레임이 입력에 고정된다(기준 ≳30dB) |
| Seedance 2.0: 끝 프레임과 입력 B | **29.8dB**. B의 구도에 착지한다. scroll-world가 Monid에서 측정한 27.5dB보다 좋다 |
| Seedance 2.0 Fast | 30.3 / 28.9dB. 고정이 유지되므로 프리비즈로 쓸 수 있다 |
| 대조군(끝 프레임과 A) | 11.2dB. 위 수치가 우연이 아니라는 확인용이다 |
| 출력 형식 | 480p를 지정하면 **864×496**(1.742:1)이 나온다. 정확한 16:9가 아니다. 비교할 때는 스틸을 cover-fit으로 맞춰야 하고, 페이지에서는 `object-fit: cover`가 이 차이를 흡수한다 |
| 크레딧 | 스틸 3, Seedance 2.0 23, 2.0 Fast 18. 견적과 실제 차감이 같았다. 다만 2.0 1080p 8초 견적도 23으로 나와서, 해상도나 길이와 상관없이 클립당 고정일 가능성이 있다. 첫 1080p 생성 때 확인한다. 고정이 맞다면 저해상도 프리비즈로 아낄 돈은 없고, 속도 차이만 남는다 |

- 이음새 검사는 `tools/seam_check.py`로 한다(cover-fit PSNR과 대조군). ffmpeg은 맥에서 `brew install ffmpeg`, 윈도우에서 `winget install Gyan.FFmpeg`로 설치한다. seam_check는 Pillow도 필요하다(맥: `brew install pillow`).

#### 실전에서 확인한 것 (2026-10-16)

- **크레딧은 클립당 23으로 고정이다.** 1080p 12초 클립도 실제로 23이 차감됐다. 그러니 저해상도로 미리보기를 돌려도 아껴지는 크레딧은 없다(속도만 빨라진다). 비용을 줄이는 방법은 **클립 수를 줄이는 것**뿐이다.
  - 한 클립에 "장면 다이브 + 다음 장면으로 비행"을 같이 넣는다. 각 클립은 이전 클립의 실제 마지막 프레임에서 시작하고, `last_frame`은 다음 장면 스틸로 준다. 장면이 3개면 클립 3개(78크레딧)로 끝난다. 다이브와 커넥터를 따로 만드는 B 구조로 가면 클립이 5개(124크레딧) 필요하다.
  - GPT-Image-2 스틸은 4K도 3크레딧이다. 이미지 편집은 2크레딧이다.
  - **그러니 영상은 항상 `resolution: "1080p"`로 생성한다.** 720p로 만들었더니 데스크톱에서 화질이 부족했다.
  - 이미 저해상도로 만든 클립은 Topaz 업스케일(×2, 클립당 3크레딧)으로 1440p까지 올린 뒤 1920×1080으로 다시 인코딩하면 된다. 이 경우 이음새 PSNR은 거의 변하지 않는다(18.6/20.7 → 18.4/20.6dB).
- **Seedance는 입력 프레임을 약 1.02배 확대해서 시작한다.** 그대로 체인을 이으면 이음새마다 2%씩 줌이 튄다.
  - 대응: 경계 프레임을 올리기 전에 1/1.02로 줄이고, 가장자리는 배경색으로 채운다. 이렇게 하면 다음 클립의 첫 프레임이 1.00 배율로 정렬된다.
  - 줌을 보정하지 않고 스틸과 비교하면 첫 프레임 PSNR이 약 19~20dB로 나온다. 보정하면 31.7 / 27.8dB다. 이음새 검사를 할 때는 줌 보정 여부를 함께 적는다.
- 체인을 실제로 이었을 때 이음새 PSNR은 18.6~29.9dB였다. 눈으로 확인해도 구도가 튀는 곳은 없었다.
- 영상 무게: 1080p 12초 클립 3개가 데스크톱 약 36MB, 720p 크롭본이 약 10MB다. Blob으로 받되, 현재 구간과 인접 구간을 먼저 받는다.
- 시각 확인: 클립 안에서 카메라가 사무실에서 위로 빠져나와 언덕 위를 날아 카페로 내려앉는다. 프롬프트대로 움직였다. 스타일은 클레이 디오라마로 일관되게 유지됐다.

## 인코딩 규칙

| 대상 | 설정 |
|---|---|
| 스크럽용 영상(데스크톱) | 원본 해상도 그대로, `-preset slow -crf 25`, **`-g 8 -keyint_min 8 -sc_threshold 0`**, `-an`, `+faststart`, `unsharp=5:5:0.5~0.8` 약하게. scroll-world 원본값은 crf 20인데, 1080p 12초 레그가 10~14MB가 된다. crf 25로 낮췄더니 레그당 절반이 됐고 SSIM은 0.993에서 0.989로 거의 같았다. 데스크톱 영상 합계 20MB 이하를 목표로 한다. |
| 스크럽용 영상(모바일) | 720 너비, `-g 4`, `-preset slow -crf 26`(scroll-world 원본값은 crf 23) |
| 재생 방식 | 클립을 **Blob으로 받아 object URL로 재생**한다. 바이트 레인지를 지원하지 않는 호스트에서도 seek가 된다 |
| 프레임 시퀀스 | 960/1280/1920/2560 티어. 거친 이분할 순서(0, 끝, 32, 16, 8, …)로 먼저 받고, 진행 방향을 고려해 ±12–24프레임을 프리페치한다. LRU 캐시를 쓰고, 예산은 데스크톱 96MB(인코딩 기준) / 폰 32MB |
| 스틸 | WebP. 960px이 약 124KB, 4096px이 약 1.1MB다 |
| 파일명 | 콘텐츠 해시를 붙이고 immutable 캐시로 내보낸다 |

- all-intra는 파일을 크게 부풀린다. 8초 클립이 약 25MB가 된다. GOP 8과 Blob 조합이면 약 8MB다.
- 영상은 스틸보다 부드럽게 뭉개진다. 화질이 중요한 정지 비트는 스틸로 처리한다.

## 라이선스와 브랜드

- 레퍼런스의 그림, 마스코트, 워드마크, 카피는 **재사용하지 않는다.** 기법과 오픈 폰트(Hahmlet, Pretendard, DM Mono는 모두 OFL)만 가져온다.
- 21st.dev 컴포넌트는 상업적으로 쓰기 전에 작성자별 조건을 확인한다.
- 스타일 레퍼런스 이미지는 각 작가의 저작물이다. 무드 참고용으로만 쓴다.
