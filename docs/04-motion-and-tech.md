# 04. 모션과 기술

## 핵심 원리: 진행값 하나와 장면 배열 하나

스크롤 필름은 겉모습이 달라도 골격이 같다.

```
tall scroller (높이 = Σ 장면 vh + 100vh)
  └─ sticky stage (top:0, 100vh, overflow:hidden)
        ├─ 배경 (plate / video / canvas)
        ├─ 오버레이 (DOM, 배경과 같은 카메라를 공유)
        └─ 크롬 (카피, 라벨, 그리드, 버튼)
scroll → progress 0..1 → 현재 장면 + 장면 내 local u → 렌더
```

- **모든 것은 `scenes` 배열 하나에서 읽는다.** 스크롤 길이(`vh`), 전환(`mode`, `tin`), 카메라 키프레임(`cam`), 카피, 오버레이를 모두 이 배열에 둔다. 연출을 바꾸려면 배열만 고친다.
- **스크롤은 하이재킹하지 않는다.** 네이티브 스크롤과 CSS sticky를 쓰고, 표시값만 부드럽게 따라가게 한다.

```ts
// 프레임레이트와 무관한 지수 스무딩. τ ≈ 45ms
k += (target - k) * (1 - Math.exp(-Math.min(dt, 64) / 45));
if (Math.abs(target - k) < 6e-5) stopLoop();   // 멈춰 있을 때는 rAF도 멈춘다
// scroll-world는 고정 lerp 0.18/frame을 쓴다(더 단순하고, 주사율에 따라 체감이 달라진다)
```

- 스무딩 라이브러리(GSAP ScrollTrigger, Lenis)는 **필요 없다.** 두 레퍼런스 모두 직접 짠 10줄짜리 루프로 해결했다. 라이브러리는 일반 섹션의 reveal 정도에만 선택적으로 쓴다.

## 기술 티어

| 티어 | 구성 | 필요 에셋 | 무게 | 언제 |
|---|---|---|---|---|
| **T0** 에디토리얼 정적 | 일반 섹션과 reveal(IntersectionObserver 또는 CSS scroll-driven animation) | 사진·일러스트 몇 장 | 가벼움 | 투어, FAQ, CTA, 그리고 모든 폴백 |
| **T1** 스틸 필름 | sticky stage, 고해상도 스틸 플레이트, `{x,y,z}` 카메라를 CSS transform으로, 크로스페이드 | 장면당 4K 스틸 1장 | 중간 | **기본 추천.** 노력 대비 효과가 가장 크다 |
| **T2** 영상 스크럽 | T1에 `video.currentTime` 스크럽(scroll-world 엔진) 또는 WebP 프레임 시퀀스 추가 | 장면 클립과 커넥터 클립 | 무거움 | 카메라가 실제로 공간 안으로 들어가야 할 때 |
| **T3** WebGL 필름 | 셰이더 하나로 전환 2~3종, 그레인·하프톤, 페이퍼 모드 | T1·T2 에셋과 전환 설계 | 무거움, 고난도 | 시그니처 전환이 브랜드의 핵심일 때 |
| **TC** 코드 필름 | 결정적 `render(progress)`로 Canvas 2D, three.js, WebGL을 직접 그린다(lemo-opuscar 방식) | 거의 없음(폰트, 소수의 텍스처) | 가벼움, 개발 시간이 든다 | 영상 없이 카메라 움직임이 필요할 때. 코드로 그리는 스타일(인포그래픽, 블루프린트, 스크린캐스트) |

- 이 티어는 **누적**된다. T3를 만들어도 T1(WebGL 없음)과 T0(reduced-motion, 실패)가 폴백으로 함께 있어야 한다. WebGL2가 없다고 안내문만 띄우고 끝내지 않는다.
- 필름 구간과 일반 섹션은 티어를 따로 고른다.

## 카메라

- 카메라는 고정 무대 좌표(예: 2048×1152)에서 `{x, y, z}`로 정한다. 키프레임 사이는 smoothstep으로 보간한다.
- **배경과 오버레이는 같은 카메라를 공유한다.** DOM 오버레이에는 `translate3d(W/2 - x*z, H/2 - y*z) scale(z)`를 준다. 그래야 마스코트와 스크린이 그림에 붙어 있다.
- 대부분의 비트는 **그림 한 장 위의 느린 푸시인**이면 충분하다. 큰 움직임은 전환 구간에 아낀다.
- 세로 화면(portrait)에서는 비트별로 카메라를 다시 정한다. 주인공이 세로 크롭 안에 들어와야 한다.
- 해상도는 `ceil(max(vw/W, vh/H) × W × min(dpr,2) × 그 비트의 최대 줌)` 이상인 가장 작은 변형을 고른다.
- **방 하나를 카메라로 돌기**: 장면마다 그림을 바꾸지 않고, 벽과 책상이 있는 공간 하나에 물건을 배치한 뒤 카메라(숙임 θ, 바라보는 점 T, 거리 d)만 움직이는 방법도 있다. 장면이 바뀌어도 공간이 이어져서 "이동했다"는 감각이 생긴다. CSS 3D(`perspective` + `preserve-3d`)로 충분하다.
- **바라보는 점이 회전보다 앞서 간다**: 카메라를 숙이거나 들 때 T를 θ보다 짧은 구간에서 먼저 도착시킨다(실측 예: θ 0.18→0.70, T 0.18→0.54). 둘을 같은 곡선으로 움직이면 감속하는 끝부분에서 떠나는 면(벽)이 화면 위에 납작한 띠로 오래 남고, 그 위의 글자가 기울어진 이탤릭처럼 읽힌다.
- 정거장 사이 구간의 끝값은 다음 정거장의 카메라 값과 정확히 같아야 한다. 그래야 경계에서 카메라가 튀지 않는다.
- **DOM과 WebGL 겹치기**: 3D 모델(예: 노트북 몸체)만 WebGL로 그리고 그 화면은 실제 iframe을 CSS 3D로 얹을 수 있다. CSS 카메라 값을 three.js로 그대로 옮긴다(y축만 뒤집는다). WebGL 캔버스는 DOM을 가리지 못하므로, 둘이 겹치는 구간 전에 DOM 물건을 어둠에 잠그거나 감춘다.

## 타이밍과 이징

| 용도 | 값 |
|---|---|
| UI 기본 | ease-out `cubic-bezier(.2,0,0,1)`, 80 / 120 / 200 / 300ms |
| 헤드라인 span reveal | `cubic-bezier(.2,.8,.2,1)` 620ms |
| 캐릭터 등장(squash & stretch) | `cubic-bezier(.22,.68,.24,1)` 650ms, 160ms 간격으로 순차 |
| 인트로 자동 스크롤 | easeInOutCubic 1450ms |
| 스크롤 스크럽 값 | smoothstep `x*x*(3-2x)` |
| 장면 체류(linger) | scroll-world `lingerEase`: 카피가 정점일 때 카메라가 잠시 머문다(L ≤ 0.6) |
| 큰 순간 앞의 숨 | 구간의 약 10%(예: 0.15~0.25)를 아무것도 움직이지 않게 비운다 |
| 정거장 스냅 | 스크롤이 멈추고 약 450ms 뒤, **가던 방향의** 정거장이 가까우면 `scrollTo`로 붙이고 아니면 그 자리에 둔다. 반대 방향으로는 끌지 않는다(천천히 굴리는 사람이 앞 장면에 붙잡히지 않게) |
| 화살표 버튼 활공 | 다음 정거장까지 사인 곡선으로 고르게 흐른다. 휙 넘어가면 공간 이동이 느껴지지 않는다 |

- 장면 하나의 내부 시간표는 비트를 겹쳐 짠다. 예: 정지 0~0.12 → 걸쇠 풀림 0.12~0.26 → 카메라 숙임 0.18~0.70 → 물건 낙하 0.20~0.86. 앞 비트가 끝나기 전에 다음 비트가 시작되어야 끊기지 않는다.

## 결정적 렌더 원칙 (모든 스크럽 연출에 적용)

스크롤은 앞뒤로 움직인다. 그래서 스크롤이 구동하는 그림은 **진행값만의 순수 함수**여야 한다. lemo-opuscar의 `render(t)` 계약을 `render(progress)`로 바꿔서 쓴다.

- 이전 프레임의 상태를 누적하지 않는다. 파티클, 지터, 노이즈는 모두 `hash(seed + index)`로 계산한다. `Math.random()`과 `Date.now()`는 쓰지 않는다.
- 단, 스무딩된 표시값(위의 τ≈45ms)과 시간 기반 "숨쉬기"(지터 루프, 아이들 애니메이션)는 이 함수 바깥에 두고 겹쳐 그린다.
- 화면 좌표는 world→screen 함수 하나로만 얻는다. 카메라를 공유하는 것과 같은 원리다.
- 스톱모션·픽셀 룩은 **조각의 포즈만** 양자화한다(`pose = floor(p * N) / N`). 카메라와 조명은 매 프레임 부드럽게 둔다.
- 텍스트는 그림에 굽지 않고 DOM 텍스트로 둔다. `TEXTS(progress)`처럼 보이는 텍스트를 보고하게 하면 읽기 시간 검사를 자동화할 수 있다.
- 장면은 `{ range, enter, leave, progress, wake, sleep }` 인터페이스로 붙인다. 되감으면 흩어진 것이 다시 모이는 식으로, 앞으로 갈 때의 사건도 진행값 경계(예: 0.5) 하나로 되돌릴 수 있어야 한다.
- **루프는 하나, 구역별로 잠든다.** 구역마다 이름으로 등록하고, 할 일이 없으면 `false`를 돌려 잠든다. 깨어 있는 구역이 없으면 rAF 자체를 멈춘다. 깨어난 첫 프레임에는 쌓인 dt를 버린다(물리가 튀지 않게).
- 물리(목줄, 흔들림, 던진 카드)는 진행값 함수 바깥에서 돌리고, 장면은 물리의 **목표값만** 바꾼다. 그래서 되감기와 직접 조작이 함께 성립한다.

## 손으로 만지는 물건

- **매달린 명함/사원증**: verlet 끈 끝에 카드를 단다. 고정점은 화면 위 밖으로 올리고 그만큼 끈을 늘린다(고정점이 화면 끝에 붙어 있으면 끌어 올릴 때 끈이 위 끝을 따라 눕는다). 첫 진입은 옆에서 놓은 것처럼 호를 그리며 떨어지게 하고, 감쇠를 약하게 시작해 약 3초에 걸쳐 평소 값으로 올린다.
- 손대기 전 힌트는 화살표 대신 **보이지 않는 손**이 물건을 살짝 밀고 뒤집었다 돌려 놓게 한다. 데스크톱은 커서가 120px 안에 오면 아주 약하게 끌리는 자석을 더한다.
- 무거운 셰이더 효과(예: 워드마크를 부풀린 3D 글자)는 정밀 포인터 데스크톱에서만 켠다. 휴대폰과 reduced-motion은 SVG 필터 같은 가벼운 근사로 대신한다. 부풀기는 글자 마스크에서 부호 거리장(Felzenszwalb EDT)을 한 번 구하고, 높이 `h = A·k·sin(π/2·d/r)`의 돔을 레이마칭하는 방식으로 만들 수 있다.

## 에셋 로딩 순서

- 첫 화면에서 보이지 않는 이미지는 첫 화면 요청에서 뺀다. 사용자가 움직이기 시작하면(p > 0.01) 바로, 움직이지 않아도 첫 화면 로드 뒤 약 1.5초 쉬었다가 받는다. 너무 늦게(p > 0.08) 시작하면 휴대폰에서 그 장면이 올 때까지 다 받지 못한다.
- 무거운 3D 모델(glb)도 같은 규칙을 따른다. 첫 화면과 함께 요청하지 않는다.
- GitHub Pages는 한꺼번에 요청이 몰리면 429를 돌려줄 수 있다.

## 오프닝 시퀀스

1. **첫 프레임은 JS 없이 칠한다.** sticky stage의 CSS 배경에 첫 플레이트를 저해상도로 넣는다.
2. 스플래시는 첫 장면이 **실제로 준비될 때까지만** 띄운다. 진행률 공식 예시는 `0.3×첫 플레이트 + 0.2×첫 GPU 프레임 표시 + 0.5×다음 장면 프레임 70%`이고, 최소 1500ms, 퇴장 450ms다. 사용자가 8px 이상 스크롤하면 바로 걷어낸다.
3. 등장을 단계적으로 연출한다. 헤드라인 0.25s, 서브 0.5s, 초점 버튼 1.2s 순이고, 캐릭터는 1850ms부터 160ms 간격으로 나온다.
4. 실패 시 재시도 버튼과 메시지를 둔다. 같은 프레임이 3회 실패하면 띄운다.

## 제품 투어 (실제 UI)

- 높이 1000svh(모바일 700svh)의 sticky 2단 구성이다. 왼쪽에는 기능 라벨, 바뀌는 h3, 설명, 스텝 점이 있고, 오른쪽에는 제품 창이 있다.
- 스텝은 스크롤 비율 임계값으로 정한다. 투명 앵커에 `scroll-snap-align:start; scroll-snap-stop:always`를 주고 html에는 `scroll-snap-type: y proximity`를 줘서 스텝마다 멈춘다.
- **데모 빌드가 있으면 iframe과 postMessage로 붙인다.** 부모가 `{phase}`를 보내고 자식이 `ready`, `presented`로 답한다. `presented`가 오기 전에는 CSS 스켈레톤을 보여 준다. iframe에는 `pointer-events:none; inert`를 주고, 접근 가능한 카피는 부모 DOM에 둔다.
- 데모 빌드가 없으면 스크린샷 6~8장을 크로스페이드한다.
- **무거운 렌더러는 한 번에 하나만 살려 둔다.** 투어가 화면을 덮으면 필름을 "파킹"한다. GL을 해제하고 캔버스를 1×1로 줄인다.

## T0 깔끔형 장치 (Clear 버전)

Clear 버전은 스크롤 진행값을 연출에 쓰지 않는다. **모션은 의미가 있는 곳에만** 둔다.

### 스크립트 제품 데모 (가장 중요한 부품)

영상이나 이미지가 아니라 **HTML과 React로 재현한 제품 화면**이 정해진 시나리오를 재생한다. 어떤 DPR에서도 선명하고, 현지화가 쉽고, 가볍다.

- 구조: 순수 리듀서(`timeline.ts`, 상태 `recording → paused → generating → done` + `REPLAY`)와 언어별 스크립트 파일(`script.ts`)로 나눈다. 시나리오는 `templates/content.md`의 데모 시나리오를 그대로 쓴다.
- 타이밍(실측 기준):

  | 상수 | 값 |
  |---|---|
  | 타자 속도 | 18ms/자 |
  | 원문 유지 | 700ms |
  | 요약 유지 | 1300ms |
  | 생성 중 | 1900ms |
  | 전체 자동 재생 | 약 21.5초 후 `paused`에서 멈춤 |

- 장치:
  - 타이프라이터.
  - **문단 완료 워시**: 요약 블록이 opacity 0→1, y 10→0으로 0.35s easeOut 등장한다. 그 위로 브랜드 틴트가 scaleX 0→1로 0.6s 동안 왼쪽에서 오른쪽으로 지나가고, 0.6s 뒤 0.8s 동안 사라진다. 왼쪽 2px 액센트 바도 함께 사라진다.
  - 채팅처럼 바닥을 따라가는 자동 스크롤: 바닥에서 40px 안쪽에 있을 때만 고정하고, 사용자가 위로 올리면 놓는다.
  - 가짜 레벨 미터: 막대 5개, 2.2s 무한 반복, 막대마다 0.12s 시차.
  - 마지막에 **"이제 ○○해보세요" 필 + 툴팁**을 띄워 첫 클릭을 유도한다.
- **레퍼런스보다 낫게 만들 점**:
  - 화면에 30% 이상 보일 때 시작한다(IntersectionObserver).
  - 화면 밖으로 나가면 멈춘다.
  - 폰에서는 정적 이미지나 축약 시나리오로 대체한다.
  - 데모 코드는 별도 청크로 나눠 지연 로드한다.
- 클릭 로그를 남기면 데모가 관여도를 재는 계측 장치 역할도 한다.
- **상위 버전: living-screencast**([refs/lemo-opuscar.md](refs/lemo-opuscar.md)). 데모 안에서 카메라가 커서 쪽으로 밀고 들어가거나, 랙포커스나 휩팬으로 시선을 옮긴다. 픽셀 마스코트가 실제 UI 요소의 윗변 위에 서서 소프트웨어의 동작을 연기한다(서 있을 위치는 매 프레임 DOM을 측정해 정한다). 커서는 사용자, 마스코트는 소프트웨어로 역할을 나눈다. 에이전트나 AI 제품이라면 "보이지 않는 일"을 보여주는 장치가 된다.

### 그 밖의 장치

| 장치 | 구현 |
|---|---|
| 로고 마키 | CSS만 쓴다. 트랙을 2벌 복제하고 `translate3d(-50%)`로 60s linear 무한 반복한다. 2번째 벌은 `aria-hidden`. 가장자리는 `mask-image: linear-gradient(90deg, transparent, #000 8%, #000 92%, transparent)`로 흐리게 한다. 로고는 흑백 85%로 두고, 호버하면 원색으로 돌아온다(300ms) |
| 서명 선 드로우인 | SVG 패스 하나에 `clip-path: inset(0 100% 0 0)`을 걸고, 25% 보이면 `inset(0)`으로 1.5s `cubic-bezier(.22,1,.36,1)` 전환한다. `stroke-dashoffset`보다 튼튼하다 |
| 캐러셀 | `translate3d` 500ms ease-out, 버튼 조작. 가장자리는 흰색 그라데이션으로 흐리게 한다 |
| 아코디언 | `max-h`와 opacity를 300ms로 전환 |
| 호버 언어 | 버튼은 `opacity .8`, 200ms. 일부러 단조롭게 둔다 |

- 라이브러리는 framer-motion 하나이고, **데모 안에서만** 쓴다. 섹션 reveal은 넣지 않거나 IntersectionObserver와 CSS로 처리한다.
- reduced-motion: 타이프라이터는 전체 텍스트를 즉시 보여주고, 워시·미터·스태거·마키·드로우인은 모두 끈다.

## 스택 (제안, 미확정)

- 필름 엔진은 **바닐라 TS 모듈**로, 프레임워크와 독립적으로 만든다. 두 레퍼런스가 모두 이 방식이다.
- 페이지 껍데기는 **Next.js App Router**로 만든다(SEO, 이미지 변형, 폰트). 일반 섹션 컴포넌트는 21st.dev(React, Tailwind, shadcn)에서 골라 쓴다. → [refs/21st-dev.md](refs/21st-dev.md)
- 모든 버전(Film / Hybrid / Clear)은 같은 콘텐츠 모델과 토큰을 쓰고, 레이아웃만 갈아 끼운다. → [07-versions.md](07-versions.md)
- **랜딩은 제품 앱과 번들을 분리한다.** 레퍼런스는 랜딩이 앱의 루트 라우트에 붙어 있어서 JS가 약 0.9MB, HTML이 279KB(전체 앱의 i18n 포함)였다. 랜딩 전용 코드는 4KB뿐이었다.
